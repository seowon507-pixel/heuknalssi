# nong · 흙날씨

농업 종사자가 지역·작물·재배 조건을 입력하면 공개자료의 준비 상태,
확인할 위험과 다음 행동을 보수적으로 안내하는 해커톤 프로젝트입니다.

## 현재 상태

- 현재 제공 범위는 재배 중 생육 점검이며, 시작할 때 작물별 재배 환경과
  생육 상태를 확인
- 재배 전 환경 분석은 추후 업데이트 예정이며 현재 지원 기능으로 시연하지 않음
- 기존 반응형 UI와 `backend-v3` HTTP API 연결 완료
- 세션·CSRF·위치 후보 확인·분석·보고서 흐름 구현
- 실제 API 자료와 운영 준비 보류(`HOLD`) 상태를 화면에서 명확히 구분
- 5개 작물의 공식 근거 기반 기온·토양 pH·수치형 위험 규칙 구현
- 서울 25개 자치구를 포함한 33곳의 행정구역 코드와 기상청 관측소 매핑 구현
- 기상청 1991–2020 월별 기후평년을 빌드 시 정적 JSON으로 변환
- 기상청 단기예보와 농경지화학성 통계정보 V2의 지역 pH 분포 연동
- 날씨·지역 토양 근거를 함께 설명하고 작물별 점검 행동을 제시
- Google AI가 검증된 분석 근거만 선택하는 농장 분석 도우미 제공
- 기상·토양·예보를 따로 보여주는 현재 농장 상태 카드 제공
- 검수 규칙 가중치만으로 산출하고 산식을 함께 공개하는 생육 적합도 점수
- 발행 예보와 ASOS 실측을 대조한 예보 정확도 배지
- 사용자 토양검정 pH·EC·유기물·유효인산·치환성 양이온 등록 흐름 제공
- PWA 설치와 Web Push 알림 제공 (앱을 나가 있어도 도착)
- SmartFarm은 사전점검 `READY`이고 지원 조합일 때만 별도 참고자료로 요청
- 분석 결과는 Supabase 공유 저장소에 보관하며, 미설정 시 메모리로 물러남
- 요청 앞뒤로 필요한 키만 되살리고 바뀐 값만 반영해 인스턴스 전환을 견딤

## 실행

Node.js 22 이상이 필요합니다.

```sh
npm start
```

브라우저에서 <http://localhost:3000>을 엽니다.

이 명령은 `.env`의 API 키를 백엔드에서만 불러와 외부 자료를 요청합니다.
더미 자료로 대체하지 않으며, 자료가 없거나 검증되지 않으면 `HOLD`로
표시합니다.

안전 기본 상태는 다음 명령으로 확인할 수 있습니다.

```sh
npm run start:safe
```

검수된 외부 runtime과 API 키를 연결하는 방법은
[`11_UI_백엔드_연결_가이드.md`](./11_UI_백엔드_연결_가이드.md)를
참고하세요.

API 없이 검수된 정적 규칙·지역 매핑만 백엔드에 로드하는 방법은
[`backend-v3/runtime/README.md`](./backend-v3/runtime/README.md)를
참고하세요. 필지의 실제 pH·EC, 중기예보 세부 구역, 필지별 최근 관측소
거리는 추정하지 않으며 검증 전까지 `HOLD`입니다.

이 모드에서는 공공데이터 키가 있을 때 기상청 단기·중기 어댑터와
농경지화학성 통계정보 V2의 지역 pH 분포를 활성화합니다. 토양 통계는
법정동 코드에 대응하는 지역 분포이며 사용자의 필지 실측값으로 표시하지
않습니다. 필지 pH·EC는 별도 토양검정 결과가 필요합니다.
`GOOGLE_AI_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_API_KEY` 중 하나가 있으면
농장 분석 도우미가 활성화됩니다. 키는 백엔드에서만 사용합니다.

Supabase 스키마·RLS·RPC 마이그레이션은 `supabase/migrations/`에 있습니다.
`SUPABASE_URL`과 `SUPABASE_SECRET_KEY`를 채우면 세션·위치 후보·분석 결과가
서버리스 인스턴스 사이에서 유지되고 사전점검의 `capabilities.persistence`가
`SHARED_KV`로 바뀝니다. 비워 두면 메모리로만 동작하며 `NOT_AVAILABLE`로
표시합니다. 표들은 RLS를 켜 두고 정책을 만들지 않아 `service_role` 외에는
접근할 수 없습니다. `SUPABASE_SECRET_KEY` 또는 기존
`SUPABASE_SERVICE_ROLE_KEY`는 서버 전용 비밀이며 브라우저에 노출하면
안 됩니다.

## 검사

```sh
npm run verify
```

UI 구조·제품 계약, 백엔드 정적 검사와 전체 테스트를 한 명령에서 검사합니다.
동일한 검사는 GitHub Actions에서도 브랜치 push와 pull request마다 실행됩니다.

## 주요 경로

- `08_흙날씨진단_UI_샘플.html`: 제품 UI 구조와 스타일
- `ui-integration/ui-shell.mjs`: 온보딩·접근성·화면 조작
- `ui-integration/backend-client.mjs`: 실제 API 계약과 결과 렌더링
- `ui-integration/dev-server.mjs`: 동일 출처 개발 서버와 보안 헤더
- `backend-v3/`: 결정론적 분석 API와 테스트
- `product_first_baseline/`: Product-first 실제 화면 및 목표 시안 증거
- `07_`~`11_` 문서: 기획, 서비스 로직, 백엔드 평가 및 연결 기록
- `PRODUCT_FIRST_PRD.md`: 제품 우선 개발 기준
