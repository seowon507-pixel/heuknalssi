# UX·접근성·실사용자 여정 감사

## 1. 평가 대상과 실행 환경

- 대상: `demo1` 브랜치, 기준 커밋 `127dfb3`
- 실제 실행: `http://localhost:3000/`, Codex 인앱 브라우저
- 화면 크기: 데스크톱 `1440×900`, 모바일 `390×844`
- 실제 조작 범위: 저장 농장 복원, 조건 변경 5단계, 위치 자동완성·무결과, 사과·오이·상추 다중 선택, 작물별 재배 조건·생육 단계, 최종 확인·분석, 작물 결과 전환, 농장 추가 진입·취소, 추가 서비스, 마이페이지, 큰 글씨·고대비, 새로고침 후 설정 지속성, 빠른 이동 모달
- 초기 브라우저에는 저장 농장이 있었다. 따라서 완전히 비어 있는 새 프로필의 첫 설치는 재현하지 않았고, `＋ 농장 추가`로 초기화된 입력 흐름을 대신 확인했다.
- 사람 대상 사용성 조사는 하지 않았다. 아래 페르소나 평가는 모두 `SIMULATED_USER_REVIEW`다.
- `.env`와 비밀값은 열지 않았다. 제품 코드는 수정하지 않았다.

## 5. 심각도순 발견 사항

### P1-1. 모바일에서 다중 농장 추가·전환을 완료할 수 없다

- 재현: 390×844에서 대시보드와 하단 메뉴 확인. 대시보드·추가 서비스·마이페이지만 있고 농장 목록/추가 버튼이 없다. `조건 바꾸기`는 현재 농장 편집이며 새 농장 추가가 아니다.
- 영향: 여러 농장 운영자는 현장에서 핵심 작업을 시작할 수 없다. 데스크톱에서 만든 다른 농장을 모바일로 전환하는 것도 불가능하다.
- 근거: 모바일 하단 메뉴 `08_흙날씨진단_UI_샘플.html:2938-2942`; 농장 기능이 사이드바에만 있음 `ui-integration/backend-client.mjs:3783-3817`; 모바일 사이드바 숨김 `08_흙날씨진단_UI_샘플.html:663-690`.
- 최소 개선: 모바일 상단의 현재 농장명을 누르면 농장 선택 시트를 열고, 마지막 항목에 `농장 추가`를 제공한다. 현재 농장과 작물 수를 함께 표시한다.

### P1-2. “선택 저장” 문구와 달리 동의 없이 농장 설정이 자동 저장된다

- 재현: 최종 확인에서 저장 동의를 체크하지 않은 채 3종 분석. 분석 완료 뒤 사이드바에 서울 강남구 농장이 저장되고 새로고침 후 자동 복원됐다.
- 영향: 사용자는 선택하지 않은 저장이 일어났다고 느끼며 개인정보·위치 신뢰가 무너진다. 공유 기기에서는 다음 사용자가 이전 농장 정보를 볼 수 있다.
- 근거: UI는 `이 기기에 농장 설정을 저장합니다. (선택)` `08_흙날씨진단_UI_샘플.html:3091-3094`; 성공 시 `writeStoredSession` 무조건 실행 `ui-integration/backend-client.mjs:955-965`; `saveConsent`는 읽기만 하고 저장 조건으로 쓰지 않음 `:4433-4451`.
- 최소 개선: 동의가 true일 때만 영구 저장한다. 동의가 없으면 현재 세션만 유지하고, 저장된 경우 대시보드에서 `이 기기에 저장됨` 및 삭제 진입을 제공한다.

### P1-3. 성공한 저장 농장 복원 뒤에도 로딩 문구가 영구히 남는다

- 재현: 저장 농장이 분석까지 정상 복원된 뒤 `조건 바꾸기` 또는 `농장 추가`를 열면 모든 단계 상단에 `지난번 설정을 불러오는 중입니다.`가 계속 보인다. 데스크톱·모바일 모두 재현했다.
- 영향: 사용자는 입력을 시작해도 되는지, 결과가 최신인지 판단하지 못한다. 본선 시연에서는 성공 상태와 로딩 상태가 동시에 보여 신뢰를 크게 훼손한다.
- 근거: `restoreSavedSession`이 loading으로 바꾼 뒤 성공 경로에서 ready로 복귀하지 않음 `ui-integration/backend-client.mjs:507-560`.
- 최소 개선: 복원 성공 직후 현재 런타임의 ready/hold 상태를 다시 렌더링한다. 로딩·성공·부분자료·오류가 상호 배타적이어야 한다.

### P1-4. 다중 작물 재배환경 그룹의 접근 가능한 이름이 모두 같다

- 재현: 오이·상추를 함께 선택한 3단계에서 화면 독해 결과 두 그룹 모두 `group “재배 환경”`, 각 라디오도 동일한 `노지/시설흙/시설물`로 노출된다.
- 영향: 화면낭독기 사용자는 어느 선택이 오이인지 상추인지 알 수 없어 잘못된 환경으로 분석할 수 있다.
- 근거: 동적 fieldset legend가 고정 `재배 환경` `ui-integration/ui-shell.mjs:216-239`. 반대로 생육단계는 `${작물} 생육단계`를 사용 `:304-355`.
- 최소 개선: legend를 `오이 재배 환경`, `상추 재배 환경`으로 만들고 검증 오류도 해당 작물 카드에 연결한다.

### P1-5. “사진·센서값을 추가하면 더 정확”이라는 핵심 CTA가 실제 분석과 연결되지 않는다

- 재현: 대시보드 점수 설명은 사진·센서값 추가를 권한다. 입력 마법사의 작물 사진은 미리보기만 제공하고 센서 입력 화면은 없다. 분석 요청에도 사진·센서 필드가 없다.
- 영향: 사용자는 사진을 넣으면 결과가 좋아졌다고 오해할 수 있고, 존재하지 않는 센서 입력을 찾는다. 분석 신뢰와 행동 완결성을 동시에 훼손한다.
- 근거: 권고 문구 `ui-integration/backend-client.mjs:2002-2008`; 사진 미리보기만 구현 `ui-integration/ui-shell.mjs:646-665`; 실제 전송 입력에 없음 `ui-integration/backend-client.mjs:4433-4452`.
- 최소 개선: 현재는 문구를 `현장 사진과 센서값을 따로 기록해 함께 확인하세요`로 낮추고 결과에 반영되지 않음을 명시한다. 실제 연결 전에는 정확도 향상 CTA로 표현하지 않는다.

### P2 발견 사항

1. 모바일 대시보드 높이가 4,436px이며 상단 행동 카드와 아래 종합 가이드·요약에서 같은 행동과 이유가 반복된다. 상단은 유지하고 아래는 접힌 `근거 자세히`로 합친다.
2. 모바일 마이페이지가 3,570px이고 토양 입력·기기 이관·접근성·알림·데이터 출처·개인정보가 한 레벨에 있다. `내 농장 자료 / 알림·화면 / 데이터·개인정보` 3그룹으로 나눈다.
3. 큰 글씨는 모바일 본문 17→17.92px만 변하고 H1은 28px 그대로였다. 설정은 새로고침 후 `보통`으로 돌아왔다. 최소 125~130% 배율과 지속 저장, 확대 시 320px 폭 검증이 필요하다.
4. 작물 버튼 전환 뒤 포커스가 `body`로 이동했다. 선택 버튼에 포커스를 유지하고 결과 제목 또는 상태 요약을 polite live region으로 공지해야 한다.
5. 모바일 예보 카드의 나머지 날짜는 가로 스크롤이며 본문 오른쪽 최대 647px까지 놓인다. `옆으로 밀어` 안내는 있으나 키보드·스위치 제어 사용자를 위해 날짜 목록에 명시적 초점/스크롤 조작 또는 축약 3일+더보기 대안이 필요하다.
6. 11~13px 보조 텍스트가 예보 날짜·출처·상태·사이드바에 반복된다. 대비는 대체로 읽히지만 고령·야외 사용에서 크기가 부족하다.
7. `농장 추가`를 열었다 취소한 뒤 `조건 바꾸기`를 열면 기존 편집 값이 아니라 초기화된 폼이 남았다. 취소 시 폼 스냅샷을 복구하거나 매번 활성 농장 값을 다시 주입해야 한다.
8. 마이페이지의 판정 한계 상세에는 `CRITICAL SOIL UNCERTAINTY…`, `UNAVAILABLE:UNSUPPORTED` 같은 내부 코드가 노출된다. 사용자 문장으로 번역하고 원문 코드는 진단용 세부정보로 분리한다.

### P3 제안

1. 데스크톱 버튼 이름 `검색 또는 명령…`은 실제 검색 입력 없이 네 가지 빠른 이동만 제공한다. `빠른 이동`으로 이름을 맞춘다.
2. `추가 서비스`는 현재 무료 토양검정 안내 하나뿐이다. 독립 최상위 탭보다 대시보드의 `토양 정확도 높이기` 작업과 연결하는 편이 정보 구조상 자연스럽다.

## 6. 잘된 점

- 모바일 첫 화면에 지역·작물, 위험 상태, 오늘 행동 3개가 한 번에 보여 3초 이해가 좋다.
- 우선 행동이 원인 수치, 현장 확인, 재확인 시점과 연결된다.
- 위치 무결과가 입력을 막기만 하지 않고 다시 입력할 범위를 알려 준다.
- `잘 모름` 생육 단계가 있어 초보자가 거짓 정밀도를 선택하도록 강요하지 않는다.
- 지역 토양 통계가 필지 실측이 아니라는 한계를 상단 가이드에서 분명히 말한다.
- 건너뛰기 링크, H1 포커스 이동, 명령 모달 Esc 닫기와 트리거 복귀, 44px 이상 주요 터치 영역, `prefers-reduced-motion`, 고대비 모드가 구현돼 있다.
- 최종 확인에서 위치·작물·조건·생육 상태를 각각 수정할 수 있다.
- 위치 권한 거부·불가·시간초과의 복구 문구가 모두 직접 입력으로 연결된다.

### 투두 UX 원칙

- 상단 `오늘의 점검 항목`을 그대로 투두의 진입점으로 사용하고 별도 앱처럼 분리하지 않는다.
- 각 항목은 `오늘 할 일 / 당분간 주의 / 완료 / 보류` 상태, 근거, 대상 농장·작물, 재확인 시점을 가진다.
- 완료는 결과가 좋아졌다는 뜻이 아니라 “사용자가 현장 확인을 수행함”만 뜻한다.
- 한 행동이 여러 작물에 공통이면 농장 공통으로 묶고, 작물별 차이는 하위 항목으로 표시한다.
- 챗봇이 만들거나 바꾸기 전 반드시 사용자 확인을 받는다.

### 사진 비교 UX 원칙

- 지금의 `미리보기`를 분석 입력처럼 보이게 하지 않는다. 저장·전송·분석 반영 여부를 선택 직전에 명시한다.
- 농장, 작물, 촬영 시각, 생육 단계, 원본 보관·삭제 상태를 사진과 함께 유지한다.
- 비교는 같은 농장·작물의 시간순 기록으로 시작하고, 색·생육 변화는 “관찰 보조”로만 표현한다.
- 진단이나 피해 원인을 확정하지 않고 현장 확인 또는 전문가 상담으로 연결한다.

### 시즌 회고 UX 원칙

- 완료된 행동, 사진, 관측·예보 변화, 사용자가 적은 메모만 시간순으로 요약한다.
- 점수 상승을 수확 성과나 행동 효과로 해석하지 않는다.
- 다중 농장에서는 시즌 회고가 농장·작물별로 분리되고, 공통 날씨 사건만 교차 비교할 수 있게 한다.
- 회고는 대시보드의 `지난 기록`에서 진입하고 마이페이지에 넣지 않는다.

### 상용 앱 대비 제품 인상

- 일반 날씨 앱처럼 “오늘의 위험”을 빠르게 보여 주면서 농업 행동으로 번역하는 점은 차별화된다.
- 건강 관리 앱의 행동 추적과 비교하면 권고를 읽는 데서 끝나고 완료·보류·재확인 기록이 이어지지 않는다.
- 농장 관리 앱의 기본 기대와 비교하면 모바일 다중 농장 전환과 농장별 기록이 부족하다.
- 현재 인상은 “설명이 강한 분석 데모”에 가깝고, “매일 현장에서 쓰는 관리 도구”까지는 도달하지 못했다.

## 9. 최소 개선 우선순위

1. **P1 즉시:** 모바일 현재 농장 선택기와 농장 추가 진입 제공.
2. **P1 즉시:** `saveConsent`와 영구 저장 동작 일치, 저장·삭제 상태 가시화.
3. **P1 즉시:** 저장 세션 복원 성공 후 연결 상태를 ready/hold로 복구.
4. **P1 즉시:** 재배환경 legend에 작물명 포함.
5. **P1 즉시:** 사진·센서가 분석에 반영되는 듯한 문구 제거 또는 실제 연결 전 명확한 미반영 고지.
6. **P2 본선 전:** 모바일 상단 행동 이후 중복 카드 접기, 주요 정보까지의 스크롤 절반 이하로 축소.
7. **P2 본선 전:** 큰 글씨를 최소 125%로 확대하고 고대비와 함께 기기 저장, 320/390px 회귀 확인.
8. **P2 본선 전:** 작물 전환 포커스 유지·결과 공지, 내부 상태 코드 사용자 문장화.
9. **본선 후:** 투두·사진 기록·시즌 회고를 농장·작물·근거·재확인 시점의 공통 기록 모델 위에 추가.

## 10. 남은 불확실성과 실행하지 못한 검사

- 실제 50~70대 농업인, 야외 강한 햇빛, 장갑 착용, 저사양 안드로이드에서 사용성 검사를 하지 않았다.
- 위치 권한 팝업은 사용자 승인/거부가 필요한 브라우저 권한이어서 실제 거부를 실행하지 않았고 코드의 복구 문구만 확인했다.
- 완전히 비어 있는 브라우저 저장소를 삭제하지 않았으므로 최초 설치의 무저장 상태는 `농장 추가` 초기화 흐름으로 대체했다.
- 실제 두 번째 농장을 끝까지 저장해 전환하는 과정은 동의 불일치를 더 확대하지 않기 위해 중단했으며, 데스크톱 추가 진입과 저장/전환 코드만 확인했다.
- 사진 업로드는 실행하지 않았다. 현재 구현이 미리보기만 만들고 분석 요청에는 포함하지 않는 것을 코드로 확인했다.
- 화면낭독기 음성 출력, 실제 키보드 전체 탭 순서, 색각 유형별 시뮬레이션, 200% 브라우저 확대는 수행하지 않았다.
- 네트워크 지연·오프라인·부분 API 실패의 실제 화면은 역할 E 범위와 겹쳐 실행하지 않았다.
- 특정 상용 앱의 최신 버전을 직접 벤치마크하지 않았으며 비교 평가는 일반적인 날씨·건강·농장관리 앱의 정보 구조 기대치에 한정했다.
