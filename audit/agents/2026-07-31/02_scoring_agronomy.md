## 4. 확인한 흐름·파일·테스트

### 4.1 실제 계산과 상태 결정 흐름

```text
확정 위치 후보
→ 작물·재배형태·작기·생육단계 정규화
→ 작물별 CLIMATE / SOIL / FORECAST 규칙 선택
→ 기후평년, ASOS, 지역 토양통계, 필지 토양도·검정, 단기·중기예보 수집
→ 기후 이탈도 / 토양 면적비 / 최근 관측 / 예보 위험을 백엔드에서 독립 계산
→ READY·PARTIAL·HOLD와 CHECK_FIRST 등 결정
→ 검수된 행동·원인·재확인 시점 반환
→ UI가 별도로 예보점수와 토양점수를 만든 뒤 60:40으로 합쳐 `생육점수` 표시
```

백엔드의 실제 축별 계산은 권위 명세와 대체로 일치한다.

- 기후: 범위 밖 상대거리 `d`; 충족도 70% 및 핵심변수 게이트; 배 단일 목표는 합산 제외 (`backend-v3/src/domain/climate.js:8-246`)
- 토양: 지역 구간을 `FIT/UNCERTAIN/OUTSIDE` 면적비로 분류; 불확실 30% 초과 시 `PARTIAL` (`backend-v3/src/domain/soil.js:12-207`)
- 예보: 단기 우선 병합, 실제 날짜·단위·freshness 검증, 임계·지속기간 규칙 평가 (`backend-v3/src/domain/forecast.js:16-175`)
- 상태·결정: 적용 모듈별 상태와 보수적 `CHECK_FIRST/FIELD_TEST_NEXT/FACILITY_*` 게이트 (`backend-v3/src/domain/states.js:3-158`, `backend-v3/src/domain/decision.js:30-163`)
- 실측 우선순위: 사용자 토양검정 → 공공 필지 검정 → 지역 통계이며 서로 평균하지 않는다 (`backend-v3/src/application/services.js:429-462`)

문제는 그 다음 UI 투영이다.

- 예보 60%, 토양 40%: `ui-integration/crop-condition-score.mjs:1-45`
- 예보 무위험을 100점, 위험 심각도 상한과 온도 1도당 4점 감점: 같은 파일 `49-111`
- 토양 `fit×100 + uncertain×65`, 도착한 항목만 재가중: 같은 파일 `64-91`
- 85/70/50 등급 경계: 같은 파일 `155-167`
- 화면의 `생육점수`, 축 점수, `날씨 60% · 토양 40%`: `ui-integration/backend-client.mjs:1899-2008`

## 5. 심각도순 발견 사항

### P0-01. 실제 UI가 금지된 60:40 단일 생육점수를 만들고 `PARTIAL/HOLD`·결측을 무시한다

**분류:** 확인된 결함

**재현 조건**

1. localhost에서 같은 안동 농장을 선택하고 사과·오이·상추 중 하나를 분석한다.
2. 백엔드 토양이 `PARTIAL`이고 `summaryEligible=false`인지 확인한다.
3. 화면 모듈 `calculateCropConditionScore`를 같은 응답에 적용한다.
4. 각각 34·49·34점이 생성된다.
5. 더 직접적인 결측 사례로 배 토양검정에 pH 6.0만 등록한다. 백엔드는 `soil.state=HOLD`, `coverage=1/3`, 결측 6개를 반환하지만 UI는 토양 100점, 최종 72점을 만든다.

**사용자 영향**

- `생육점수`와 `양호/관심/주의`는 현재 작물 건강도나 성공확률처럼 읽힌다.
- 지역 pH 통계, 필지 토양검정, 시설 참고토양, 단·중기 외기예보가 하나의 숫자에서 같은 종류의 근거처럼 취급된다.
- `PARTIAL/HOLD`가 점수에 반영되지 않아 핵심 자료가 없을수록 남은 자료가 사실상 100%로 재가중된다.
- 시설토경에서는 외기값이 내부 환경이 아니라는 백엔드 한계를 표시하면서도 바로 옆에서 외기 점수를 합산한다.

**근거**

- `ui-integration/crop-condition-score.mjs:1-167`
- `ui-integration/backend-client.mjs:1899-2008`
- 권위 명세의 단일 점수 금지: `09_흙날씨진단_서비스로직_명세서.md:20-39`
- preflight는 오히려 `singleCompositeScore:false`, `missingValueReweighting:false`를 보증한다: `backend-v3/src/application/services.js:814-818`

**최소 개선 방향**

- `crop-condition-score.mjs`와 화면의 0~100 생육점수·등급·60:40 문구를 제거한다.
- 백엔드가 이미 반환하는 `decision`, `primaryAction`, 기후 실제 편차, 토양 세 면적비, 예보 위험, `READY/PARTIAL/HOLD`를 독립 카드로 표시한다.
- 새 가중치로 대체하지 않는다. 향후 점수는 실패 정의, 5작물 기준 데이터셋, 교정오차, 결측 계약, 농업 전문가 검수와 현장 백테스트가 먼저다.

### P0-02. 감자·오이·상추의 필수 작기를 묻지 않고 현재 달 한 달로 `userConfirmed:true`를 만든다

**분류:** 확인된 결함

**재현 조건**

1. UI의 재배 중 흐름에서 감자·오이·상추를 선택한다.
2. 작기를 입력하지 않아도 `season:"current"`와 기기 월이 전달된다.
3. `seasonFor`가 `startMonth=endMonth=analysisMonth`, `userConfirmed:true`인 `CUSTOM` 작기를 생성한다.
4. 같은 안동 자료에서 오이는 7월 단일월 `D=0.00`이지만 4~9월 요청은 `D=0.33`; 감자는 0.20 대 0.10185, 상추는 0.96 대 0.48이었다.

**사용자 영향**

- 사용자가 확인하지 않은 작기가 확정 입력처럼 저장되고 장기 기후 결과를 바꾼다.
- 오이는 7월만 보면 범위 안으로 표시되지만 실제 작기 앞뒤의 저온·고온 이탈이 사라진다.
- 권위 명세의 “필수 작기를 현재 월이나 추천값으로 자동 확정하지 않는다” 불변조건을 직접 위반한다.

**근거**

- `ui-integration/api-contract.mjs:286-305`
- `ui-integration/backend-client.mjs:4211`, `4438-4444`
- 이를 의도된 동작으로 고정한 테스트: `ui-integration/api-contract.test.mjs:245-270`

**최소 개선 방향**

- 감자는 검수 프리셋/직접 월/명시적 `UNKNOWN`, 오이·상추 노지는 시작·종료월/명시적 `UNKNOWN`을 사용자에게 받는다.
- 사용자가 답하지 않으면 제출을 막고, 명시적 `UNKNOWN`이면 현재 예보는 계속하되 기후축은 `HOLD`로 둔다.

### P1-01. 화면의 기본 생육단계 대부분이 서버에서는 `UNSPECIFIED`라 단계 전용 위험이 자동 적용되지 않는다

**분류:** 확인된 결함

UI는 월별 정적 표로 `초기 생육/한창 자라는 중/수확 무렵`을 기본 선택하고 `날짜 기준 AI 예상`이라고 표시한다. 그러나 세 값은 모두 `UNSPECIFIED`로 변환된다. 실제 단계 규칙은 배 `FLOWERING`, 감자 `TUBER_BULKING`, 시설 상추 `FLOWER_DIFFERENTIATION`뿐이다. 특히 감자가 실제 괴경 비대기여도 기본 `한창 자라는 중`을 그대로 두면 27℃ 위험은 `WARNING`이 아니라 단계 공통 `CAUTION`만 활성화된다.

근거: `ui-integration/ui-shell.mjs:276-285`, `293-352`; `ui-integration/api-contract.mjs:15-26`, `217-225`; `backend-v3/runtime/reviewed-crop-rules.js:326-393`.

최소 개선은 “AI 예상”을 제거하고 기본값을 `잘 모름/단계 공통`으로 두는 것이다. 검수된 구체 단계가 있는 작물에는 그 질문을 명시적으로 보여주고, 없는 작물은 단계별 판정을 한다고 암시하지 않는다.

### P1-02. preflight와 자동 테스트가 제품의 단일점수 위반을 탐지하지 못하고 반대로 보증한다

**분류:** 확인된 결함

- preflight 실제 응답은 `singleCompositeScore:false`, `missingValueReweighting:false`다.
- 백엔드 테스트는 “composite score 없음”을 확인하지만 UI 후처리를 검사하지 않는다.
- UI 테스트는 정적 HTML에서 과거 `55%/45%` 문자열만 찾지 않고, 다른 테스트에서는 새 `날씨 60% · 토양 40%`를 명시적으로 요구한다 (`ui-integration/product-first-ui.test.mjs:163-193`, `408-412`).
- 결과적으로 332개 테스트가 모두 통과해도 가장 중요한 안전 불변조건은 깨진다.

최소 개선은 API 응답부터 최종 DOM까지 직렬화해 `score`, `생육점수`, 축간 가중합, `PARTIAL/HOLD`의 숫자 투영이 없는지 검사하는 제품 계약 테스트를 추가하는 것이다.

### P1-03. `5작물 완료/READY`가 농업 규칙의 폭과 백테스트 품질을 과대대표한다

**분류:** 확인된 근거 한계

실제 규칙 인벤토리는 다음처럼 좁다.

- 기후: 사과 연평균기온 1개, 배 평균기온 목표 1개, 감자·오이·상추는 같은 평균기온 범위를 선택 월마다 복제
- 지역 토양 의사결정: 실제 라이브 지역통계에서는 작물별 pH 1개만 사용
- 예보: 최고·최저기온 중심이며 모든 현재 규칙의 duration이 `ANY_DAY`; 강수량·강수확률·풍속 지속위험 규칙은 0개
- 생육단계 전용: 배·감자·시설 상추 일부뿐

그런데 preflight는 이 최소 모듈 존재를 `completeCropCount:5`와 전체 `READY`로 표현한다 (`backend-v3/src/application/services.js:740-779`). 이는 코드 계약의 완결성이지 농업적 위험 커버리지나 현장 타당성 검증이 아니다.

최소 개선은 상태명을 `EXECUTABLE_RULE_COVERAGE`처럼 한정하고, 작물별 “현재 다루는 위험/다루지 않는 위험”을 함께 공개하는 것이다. 강수·풍속·배수·토성·생육단계·지속시간 규칙은 출처와 2인 검수, 실제 과거 발행 예보 백테스트가 끝난 항목만 확장한다.

### P2-01. 농업 출처 테스트가 메타데이터 존재는 확인하지만 수치가 원문과 일치하는지는 증명하지 않는다

**분류:** 재현되지 않은 위험

규칙 테스트는 HTTPS URL, 제목, 표 위치, 검토일, guidance 존재를 확인한다 (`backend-v3/test/reviewed-runtime-assets.test.js:38-78`). 이번 감사는 지시대로 실제 코드·테스트·localhost만 근거로 했으므로 외부 원문 숫자와 2인 농업 검수 사실을 독립 확인하지 않았다. 따라서 “출처 필드가 있다”와 “임계값이 농업적으로 확정됐다”를 동일시하면 안 된다.

### 농업적으로 위험한 현재 표현

| 표현 | 문제 | 권고 문구 |
|---|---|---|
| `생육점수 72점`, `양호/관심/주의` | 건강도·성공확률로 오인되며 결측과 공간범위를 숨김 | 삭제하고 `기후 조건`, `지역 토양 참고`, `가까운 예보 위험`, `자료 상태`로 분리 |
| `날씨 영향 100점` | 등록된 소수 위험 규칙에서 초과가 없다는 뜻일 뿐 강수·풍속·병해·필지 미기후가 양호하다는 뜻이 아님 | `확인한 예보 기준 초과 없음` |
| `날짜 기준 AI 예상` | 정적 월 매핑이고 서버에는 대개 `UNSPECIFIED` | `일반 시기 추정 — 실제 단계를 선택해 주세요` 또는 삭제 |
| `더 정확히 확인하려면 사진·센서값을 추가` | 현재 점수 자체가 검증됐고 사진·센서가 그 점수를 정밀화하는 것처럼 보임 | `사진·센서는 별도 현장 기록이며 현재 공개자료 판단과 합산하지 않음` |

## 6. 잘된 점

- 백엔드 도메인 결과에는 단일 score가 없고 기후·토양·관측·예보가 분리돼 있다.
- 결측은 `null`로 남고, 기후·토양 충족도 분모에서 누락 가중치를 제거하지 않는다.
- 배의 단일 목표는 종합 이탈도에 넣지 않아 거짓 범위를 만들지 않는다.
- 토양 지역통계를 평균 pH나 필지 측정값으로 바꾸지 않고 면적비와 `REGIONAL_STATISTICS`로 보존한다.
- 사용자/공공 필지 토양검정이 있으면 지역 통계보다 우선하되 자료끼리 평균하지 않는다.
- 시설수경은 토양 `NOT_APPLICABLE`, 시설토경은 `FACILITY_REFERENCE`로 분기하고 외기 한계를 결정 결과에 남긴다.
- 단기·중기 공간수준, 발행시각, freshness, 실제 임계값, 행동, 재확인 시점이 근거 객체에 연결된다.
- `UNSPECIFIED`에서는 단계 전용 위험을 만들지 않고, stale/sample 예보로 현재 위험 행동을 만들지 않는다.
- 5작물의 정확한 예보 경계와 결측 전이는 결정적으로 테스트된다.

## 7. 향후 기능과 연결되는 설계 고려사항

### 점수 권고

**현재 생육점수는 유지하지 말고 즉시 제거한다.** 단순 가중치 변경도 권고하지 않는다.

유지할 것은 다음 네 축이다.

1. 장기 기후: 실제 값, 공식 범위/목표, 물리적 편차, 무차원 이탈도, coverage
2. 토양: 실측 여부와 지역통계 여부, 적합·경계·밖 면적비 또는 실측 항목별 범위
3. 최근·향후 위험: 날짜, 공간수준, 임계, 지속기간, 위험도, 행동, 재확인 시점
4. 자료 상태: `READY/PARTIAL/HOLD`, 출처, 거리, 시점, freshness, 결측

향후 0~100 점수를 재검토하려면 최소한 5작물별 실패 사건 정의, 생육단계·재배환경별 독립 모델, 과거 발행 예보와 실제 관측의 시간 정렬, 농가 결과/현장 판정 라벨, 교정곡선과 오차범위, 외부 지역 검증, 결측 시 점수 보류 계약이 필요하다.

### 위성 식생지수·필지 경계 원칙

- 실제 노지 필지 폴리곤이 있고 사용자가 확정한 경우만 실행한다.
- 촬영일, 10m 해상도, 구름·그림자·눈 마스크 정책, 유효 픽셀 수·비율, 내부 버퍼/전체필지 fallback을 보존한다.
- NDVI는 식생 반사 관찰값일 뿐 건강도·병충해·원인·수확량·생육점수를 의미하지 않는다.
- 동일 AOI·해상도·마스크 정책의 비교 가능한 두 장면에서만 변화량을 낸다.
- 위성은 기후·토양·예보 판단을 올리거나 내리거나 종합점수에 가중하지 않는다.
- 결과는 “사진/현장 확인이 필요한 구역을 찾는 보조 근거”로만 사용하고, 품질 게이트 미달은 `HOLD`로 남긴다.

### 투두·사진·시즌 기록 연결

- 행동은 `triggerIds`, 출처, dueWindow, 재확인 시점과 함께 저장한다.
- 사진은 촬영일·농장·작물·생육단계·동의·삭제정책을 보존하고 점수 보정 입력으로 자동 사용하지 않는다.
- 시즌 회고는 당시 데이터·행동·사진의 시간순 기록이며, 없던 성과나 인과를 생성하지 않는다.

## 8. 최소 개선 우선순위

1. **본선 전 즉시:** UI 생육점수·60:40 합산·축 점수·등급을 제거하고 백엔드 독립축과 결정/행동을 그대로 표시한다.
2. **본선 전 즉시:** 감자·오이·상추의 작기를 사용자가 확인하게 하고, 미확정이면 기후 `HOLD`로 둔다.
3. **본선 전:** `초기/중기/수확` 기본값과 `AI 예상`을 제거하거나 명시적 `UNSPECIFIED`로 표시하며, 배 개화·감자 괴경비대·시설 상추 화아분화를 직접 묻는다.
4. **본선 전:** preflight 보증을 최종 UI까지 검증하는 통합 테스트를 추가한다. `PARTIAL/HOLD`, 30% 토양 경계, pH만 있는 토양검정, 시설토경을 필수 회귀 사례로 둔다.
5. **후속:** crop×stage×mode별 미지원 위험 목록을 공개하고, 강수·풍속·배수·토성·지속시간 규칙은 원문 검수와 과거 발행 예보 백테스트 후 추가한다.

승인 게이트:

- 화면과 응답 어디에도 축간 합산점수 0건
- 사용자 확인 없는 작기 `userConfirmed:true` 0건
- `PARTIAL/HOLD`가 확정 숫자·양호 등급으로 바뀌는 경로 0건
- 5작물별 원인 → 위험 → 행동 → 재확인 시점 확인
- 동일 fixture의 백엔드 상태와 최종 DOM 문구 일치

## 9. 남은 불확실성과 실행하지 못한 검사

- 외부 농업 원문 페이지의 문장·표와 각 임계값을 독립 대조하지 않았다. 이번 역할은 지시대로 실제 코드·테스트·localhost 결과만 사용했다.
- 실제 농업 전문가 2인 검수 기록과 현장 농가 결과 데이터는 저장소 근거만으로 확인할 수 없었다.
- localhost 실호출은 안동 한 위치 중심이다. 5작물·시설 분기와 경계는 확인했지만 8개 매핑 지역 전체의 라이브 결과를 반복하지 않았다.
- 실측 토양검정은 API의 사용자 등록 경로로 재현했으며 실제 농가 성적서 진위는 검증하지 않았다.
- 과거 발행 예보 백테스트는 자동 테스트의 ASOS replay 계산 통과를 확인했지만, 작물 피해·생육 결과에 대한 예측 교정이나 외부 검증 데이터셋은 확인되지 않았다.
- 실제 사람 사용 후기로 표현한 내용은 없으며, 이 보고서는 계산·데이터 독립 감사다.
