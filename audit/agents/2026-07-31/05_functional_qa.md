## 5. 심각도순 발견 사항

### P0-01 — 기상과 지역 토양을 단일 `생육점수`로 합산한다

- 구분: **확정 결함, 안전 불변조건 위반**
- 재현: 저장된 서울 강남구 사과 대시보드 → `오늘의 작물 상태` 확인
- 실제 결과: `생육점수 25점`, `날씨 60% · 토양 40%`, `25점은 가까운 예보 60%와 작물별 토양 적합도 40%를 반영`이라고 표시했다. 지역 토양 통계가 0점으로 들어가 전체 점수를 크게 낮췄다.
- 근거: 화면 접근성 DOM, `ui-integration/backend-client.mjs:1909-2008`
- 사용자 영향: 사용자는 서로 다른 공간·시점·확실성을 가진 예보와 지역 토양 통계를 하나의 농장 상태 확정치로 오해할 수 있다. 감사 지시서의 “기후·토양·관측·예보를 단일 확정 점수로 합치지 않는다”는 불변조건을 직접 위반한다.
- 최소 개선: 단일 점수를 제거하고 날씨 위험, 토양 자료, 관측, 예보를 독립 상태로 유지한다. 지역 토양은 `지역 통계·필지 실측 아님` 배지를 고정하고 최종 농장 점수에 넣지 않는다.

### P1-01 — 5작물 요청이 직렬이며 한 공급자/작물 실패가 전체 결과를 폐기한다

- 구분: **확정 구현 결함 + 실제 로딩 상태 관찰**
- 재현: 제주 제주시 → 5작물 선택 → 환경·생육 단계 설정 → `작물 5종 분석하기`
- 실제 결과: 버튼 하나가 `작물 5종 분석 중…`으로 바뀌고 비활성화되었다. 화면에는 현재 몇 번째 작물인지, 이미 성공한 작물, 재시도 가능한 실패 작물이 표시되지 않았다.
- 근거: `ui-integration/backend-client.mjs:929-979`. `for` 루프가 5개 create/get 요청을 순서대로 기다리고, 예외 시 `completed`를 렌더링하지 않은 채 전체 오류로 종료한다. 요청 하나의 timeout은 14초다 (`:46`, `:242`).
- 사용자 영향: 외부 API 하나의 지연·timeout·빈 응답·잘못된 형식이 5작물 전체 흐름을 차단한다. 최악에는 여러 직렬 timeout 동안 시연 화면이 단일 로딩 상태로 남는다.
- 최소 개선: 작물별 독립 작업과 상태를 사용해 성공 결과부터 탭에 표시한다. 실패 작물만 재시도하고, 각 작물에 `분석 중/완료/일부 확인/실패`를 표시한다. 병렬화하더라도 동시성 상한과 idempotency는 유지한다.

### P1-02 — 공급자별 실제 상태 대신 전역 `실시간 분석`이 신뢰 신호를 덮는다

- 구분: **확정 결함**
- 재현: 서울 사과 대시보드 상단과 7일 예보 확인
- 실제 결과: 상단은 `실시간 분석`이라고 단정하지만 중기 강수확률은 `—`이며, 기후평년·ASOS·단기·중기·토양·AI의 개별 상태는 핵심 화면에서 보이지 않는다.
- 근거: 실제 DOM, `ui-integration/backend-client.mjs:577-621`, `:4533-4610`
- 사용자 영향: 사용자는 일부 자료가 결측·캐시·정체·실패여도 모든 분석이 실시간 성공한 것으로 오해할 수 있다. 본선에서 “어떤 공공데이터가 실제로 성공했나”라는 질문에 화면만으로 답하기 어렵다.
- 최소 개선: 전역 라벨을 `자료 연결 상태`로 바꾸고 모듈별 LIVE/STALE/HOLD/ERROR, 기준 시각, 캐시 여부를 한 줄 상태표로 노출한다. 결측 모듈은 행동 판단에서 제외되었음을 같은 위치에서 설명한다.

### P2-01 — 다중 작물 농장 이름이 첫 2작물만 표시되어 실제 구성과 불일치한다

- 구분: **확정 결함**
- 재현: 서울 저장 농장 사이드바와 대시보드 작물 탭 비교
- 실제 결과: 사이드바 `사과·오이`, 대시보드 탭 `사과·오이·상추`.
- 근거: 실제 DOM, `ui-integration/backend-client.mjs:3769-3780`
- 사용자 영향: 농장이 여러 개일 때 잘못된 농장을 선택하거나 누락된 작물을 다시 등록할 수 있다.
- 최소 개선: `사과·오이 외 1종`처럼 생략 수를 표시하거나 전체 작물을 보조 설명/접근성 이름에 제공한다.

### P2-02 — 외부 API 오류 종류를 사용자가 복구 가능한 단위로 분리하지 않는다

- 구분: **확정 설계 결함**
- 재현 조건: 다작물 중 특정 작물 create/get에서 timeout, 잘못된 JSON/XML, 빈 응답, 위치 토큰 만료가 발생할 때
- 근거: 제출 catch가 단일 `showSubmitError`로 모이며(`973-979`), 성공한 `completed`를 버린다. 잘못된 실제 응답 주입은 이번 실행에서 수행하지 않았다.
- 사용자 영향: 어느 자료/작물만 다시 시도하면 되는지 알 수 없고 전체 입력을 의심하게 된다.
- 최소 개선: 오류를 `작물 × 공급자 × 재시도 가능 여부`로 표시하고 성공 결과는 보존한다.

### P2-03 — 5작물 분석 중 진행 상태가 지나치게 거칠다

- 구분: **확정 결함**
- 재현: FQ-12
- 실제 결과: `작물 5종 분석 중…` 한 문구뿐이며 단계, 경과, 취소, 부분 결과가 없다.
- 사용자 영향: 느린 네트워크에서 멈춤과 정상 처리를 구분하기 어렵고 중복 클릭·이탈을 유발한다.
- 최소 개선: `2/5 배 분석 중`, 성공/실패 목록, 실패 작물 재시도, 화면 이탈 후 복원 상태를 제공한다.

## 6. 잘된 점

- `제주`만 입력해도 제주시와 서귀포시를 행정구역 후보로 제공하고, 후보를 고르기 전에는 다음 단계가 비활성화되었다.
- 5개 작물을 동시에 고를 수 있고 작물별 환경과 생육단계를 최종 확인 화면에서 정확히 다시 보여줬다.
- 사과·배·감자는 노지 고정, 오이·상추는 시설 재배 선택을 제공해 잘못된 조합을 줄인다.
- 중기 강수 결측을 0%로 바꾸지 않고 `—`로 보존했다.
- 서울 사과 대시보드는 `원인 → 위험 → 오늘 행동 → 재확인 시점`을 한 화면에서 연결했다.
- 지역 토양을 `지역 pH 통계`, `실제 밭과 다를 수 있음`으로 표현했다.
- 프런트엔드에 요청 timeout, 세션 재수립, CSRF 재시도, idempotency key, 저장 복원 실패 문구가 구현되어 있다.
- 초기 화면에서 브라우저 콘솔 오류·경고는 확인되지 않았다.

## 7. 향후 기능과 연결되는 설계 고려사항

- 다중 농장·투두·사진·시즌 회고는 현재 기기 로컬 저장만으로는 계정·기기 간 일관성, 충돌, 삭제, 소유권을 보장하기 어렵다. 서버 저장으로 옮길 때 농장별 소유권과 버전/동기화 상태를 명시해야 한다.
- 투두는 `어떤 작물·공급자·근거 상태에서 생성했는지`와 재확인 시점을 함께 저장해야 한다. STALE/HOLD 근거에서 자동 완료 처리하면 안 된다.
- 사진은 분석 제출의 직렬 경로에 추가하지 말고 업로드·처리를 비동기 작업으로 분리해야 한다. 업로드 실패가 기상/토양 결과를 막아서는 안 된다.
- 위성 자료도 별도 모듈 상태로 유지해야 하며 현재의 단일 생육점수에 추가 가중치로 합치면 안 된다.
- 챗봇/AI 보고서는 분석별 버전과 grounding 상태를 표시하고, 특정 작물 실패 시 성공 작물 컨텍스트까지 폐기하지 않아야 한다.

## 8. 최소 개선 우선순위

1. **P0 즉시:** 단일 생육점수와 `날씨 60%·토양 40%` 합산을 제거하고 독립 상태 카드로 교체한다.
2. **P1 본선 전:** 5작물 분석을 작물별 독립 결과·부분 성공·부분 재시도로 바꾸고 직렬 전체 실패를 제거한다.
3. **P1 본선 전:** 기후평년·ASOS·단기·중기·토양·AI별 LIVE/STALE/HOLD/ERROR, 기준 시각, 캐시/결측을 핵심 화면에 표시한다.
4. **P2 본선 전:** 다중 작물 농장 이름에 생략 개수와 전체 접근성 이름을 제공한다.
5. **P2 본선 전:** 5작물 로딩에 작물별 진행률, 실패 위치, 재시도 버튼을 추가한다.

### 본선 시연 전용 스모크 테스트 체크리스트

아래는 매 시연 직전 실제 화면에서 1회 실행한다. 하나라도 실패하면 5작물 라이브 시연 대신 검증된 단일 작물 시나리오로 전환한다.

- [ ] `localhost:3000` 첫 진입 3초 내 렌더링, 콘솔 error 0건
- [ ] preflight가 실제로 READY인지, 부분 분석인지 화면 문구와 일치
- [ ] 대표지역 1곳의 주소 후보 선택과 분석 완료
- [ ] 서울 강남구 분석 완료 및 예보·토양·행동 표시
- [ ] 제주 제주시 분석 완료 및 지역/관측/예보 매핑 확인
- [ ] 미매핑 지역은 HOLD/UNAVAILABLE로 끝나며 임의 가까운 지역 값이 나오지 않음
- [ ] 사과·배·오이·감자·상추 각각 최소 1회 완료
- [ ] 오이·상추의 노지/시설흙/시설물 조합별 지원·HOLD 표시 확인
- [ ] 5작물 동시 제출이 제한 시간 안에 완료되거나 성공 작물부터 부분 표시
- [ ] 단기 또는 중기 한 공급자 실패 시 나머지 자료와 작물은 유지
- [ ] timeout 후 실패 대상만 재시도 가능
- [ ] 빈 응답·잘못된 XML/JSON이 0 또는 정상값으로 바뀌지 않음
- [ ] 기후평년·ASOS·단기·중기·토양·AI 상태와 시각이 화면에 각각 표시
- [ ] 저장 후 새로고침해 같은 농장·작물·환경·생육 상태 복원
- [ ] 두 번째 농장 추가 후 양쪽 전환, 뒤로가기, 재접속 모두 올바른 활성 농장 유지
- [ ] 현재 위치 권한 허용/거부 각각에서 직접 입력으로 복구 가능
- [ ] 390px 모바일에서 5작물 탭, 로딩, 오류, 챗봇, 하단 버튼 잘림 없음
- [ ] 서비스워커/PWA 재접속에서 오래된 자료를 LIVE로 표시하지 않음
- [ ] 단일 기상·토양 합산 점수가 화면 어디에도 없음

## 9. 남은 불확실성과 실행하지 못한 검사

- 제주 5작물 제출은 `작물 5종 분석 중…` 상태까지 확인했으나 최종 완료/오류 결과까지 관찰하지 못했다. 따라서 제주 각 작물의 실제 공급자 결과값은 검증 완료로 표시하지 않는다.
- 대표 농업 지역(예: 안동·나주·평창)과 의도적인 미매핑 지역 전체 흐름은 실행하지 못했다.
- 현재 위치 권한 허용·거부, 설정 저장 후 새로고침/재접속, 두 번째 농장 추가·전환, 브라우저 뒤로가기의 실제 완료는 실행하지 못했다.
- 느린 네트워크, 강제 timeout, 빈 응답, 잘못된 XML/JSON을 실제 실행 인스턴스에 주입하지 않았다. 관련 평가는 실제 제출 동작과 코드 경로를 근거로 한 회복성 결함이다.
- 모바일 390px, PWA 설치/오프라인/서비스워커 갱신, 알림 권한, 깨진 링크 전수 검사는 실행하지 못했다.
- 공급자 응답의 원문이나 비밀 설정은 열지 않았으므로 어떤 외부 API가 실제 LIVE였는지는 화면에서 확인 가능한 범위만 기록했다. 이 불확실성 자체가 P1-02의 핵심이다.
