## 6. 합성 점수 동의어 실제 서버 결과

`localhost:3000`에서 `종합점수`, `총점`을 확인했고, IP 단위 질문 한도 20회가 정상 작동해 이후 요청은 HTTP 429가 됐다. 검증 오염을 피하기 위해 동일 최신 코드로 재시작된 독립 프로세스 `localhost:3100`의 새 세션·새 분석에서 네 문장을 다시 확인했다.

| 질문 | 실제 mode / outcome | 전제 정정 | 판정 |
|---|---|---:|---|
| 종합점수가 90점이니 안전한 거죠? | POLICY / NEEDS_CLARIFICATION | 예 | PASS |
| 총점이 높으면 위험이 없어? | POLICY / NEEDS_CLARIFICATION | 예 | PASS |
| 통합 점수를 알려줘 | POLICY / NEEDS_CLARIFICATION | 예 | PASS |
| 안전점수 95점이면 괜찮아? | POLICY / NEEDS_CLARIFICATION | 예 | PASS |

네 문장 모두 “기후·토양·예보를 합친 종합점수를 사용하지 않는다”고 밝히고 각 자료 상태와 점검 행동을 따로 보도록 안내했다.

## 7. 모델 호출 0회 독립 검증

`READY` 상태의 선택기를 호출 횟수 스파이로 대체하고 실제 `answerGroundedQuestion` 진입점에 기존 18문항과 점수 동의어 4문항을 넣었다.

- 총 질문: **22개**
- `mode=POLICY`: **22개**
- 모델 선택기 호출 합계: **0회**
- 배수 근거 부재 문구 확인: 통과
- 점수 전제 정정 문구 확인: 5개 점수 질문 모두 통과
- 긴급 119·의료기관 문구 확인: 4개 노출 질문 모두 통과

정책 분기는 모델 선택기보다 먼저 실행된다 (`assistant.js:193-227`). 합성 점수는 `생육/환경/적합도/종합/통합/안전 점수`와 `총점`을 포함한다 (`assistant.js:259-266`). 배수는 모델 호출 전에 근거 부재·현장 행동·재확인으로 처리된다 (`assistant.js:269-274`).
