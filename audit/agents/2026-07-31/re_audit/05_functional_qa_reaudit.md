### 4.2 실제 공공 API 흐름

`경북 안동시 퇴계로 115`를 사용한 직접 백엔드 흐름의 관찰값은 다음과 같다.

- 주소 후보 1건, `ADDRESS_RESOLVED`
- 분석 생성 HTTP 201
- 전체 `PARTIAL`, condition `PARTIAL`, risk `READY`, decision `CHECK_FIRST`, lifecycle `CORE_READY`
- 모듈: 기후 `READY`, 토양 `PARTIAL`, 관측 `READY`, 예보 `READY`
- 보조질문 HTTP 200, mode `GOOGLE_AI`, grounded `true`
- 보조질문 섹션: `확인된 내용`, `필요한 행동`
- 실제 출처 7개: 기후평년, ASOS, 토양 3종, 단기예보, 중기예보. 토양검정 출처의 `UNAVAILABLE/NO_DATA`도 성공으로 위장하지 않고 유지했다.
- 첫 실행은 LIVE 중심, 프런트 프록시 재실행은 CACHE 중심으로 응답해 캐시 상태도 구분됨을 확인했다.

실제 preflight는 서비스 실행 상태와 배포 준비 상태를 분리했다.

- `ready: true`, `serviceState: READY`
- `deploymentReady: false`, `deploymentState: HOLD`
- blocker: `SHARED_STATE_NOT_CONFIGURED`
- persistence/device backup: `NOT_AVAILABLE`
- report: `DETERMINISTIC_TEMPLATE`, assistant: `READY`

따라서 현재 로컬 데모 기능은 동작하지만, 공유 상태가 필요한 다중 인스턴스 상용 배포 준비까지 완료된 것으로 판정하지 않는다.

### 4.3 5작물 및 부분 실패

사과·배·오이·감자·상추를 동시에 UI 계약 형식으로 요청한 실제 실행은 **5 fulfilled / 0 rejected**, 모두 HTTP 201, 총 약 4.4초였다. 작물별 독립 상태도 유지되었다.

| 작물 | 전체 | 기후 | 토양 | 관측 | 예보 |
|---|---|---|---|---|---|
| 사과 | PARTIAL | READY | PARTIAL | READY | READY |
| 배 | COMPLETE | READY | READY | READY | READY |
| 오이 | PARTIAL | READY | PARTIAL | READY | READY |
| 감자 | COMPLETE | READY | READY | READY | READY |
| 상추 | PARTIAL | NOT_APPLICABLE | PARTIAL | READY | READY |

추가 실패 주입 실행에서는 **4 fulfilled / 1 rejected**가 유지됐다. 실패는 반복 동시 호출 중 rate limit 429였고, `Promise.allSettled` 경로에서 네 성공 결과가 폐기되지 않았다. UI 정적 회귀 테스트도 실패가 있어도 완료 결과를 보존하고 부분 실패 배너를 표시하는 코드를 고정한다.

## 6. 남은 발견 사항

### P2-01 — 실패 작물 전용 재시도가 없고 반복 5작물 요청은 429에 걸릴 수 있다

- 성공한 작물을 보존하는 핵심 P1은 해결됐다.
- 그러나 부분 실패 배너는 실패 작물을 알려주기만 하고, 실패 작물만 다시 보내는 버튼이나 대기시간 안내는 없다.
- 실제 반복 동시 실행에서 한 요청이 HTTP 429로 실패했다.
- 최소 개선: 실패 결과 옆에 재시도 가능 시점과 실패 작물만 재시도하는 동작을 제공하고, 클라이언트 동시성 상한 또는 rate-limit 인지 스케줄링을 적용한다.

### P2-02 — 브라우저/시스템 뒤로가기가 마법사 상태와 연결되지 않는다

- 화면 내 `이전`과 첫 단계 `돌아가기`는 구현되어 있다.
- UI 코드에는 `popstate`, `pushState`, `replaceState` 또는 동등한 history 연동이 없다. 모바일 OS/브라우저 뒤로가기는 마법사 한 단계 이동이나 모달 닫기가 아니라 페이지 이탈로 이어질 수 있다.
- 최소 개선: 마법사·모달 진입 상태를 history에 반영하고 `popstate`에서 모달 닫기→이전 단계→페이지 이탈 순서를 일관되게 처리한다.

### P2-03 — 역사 데이터 백테스트가 아직 차단되어 있다

- 현재 LIVE/CACHE/UNAVAILABLE 전달과 결측 보존은 확인했다.
- 다만 `verify:backtest`는 과거 ASOS 및 발표 당시 예보 재생 소스가 `UNSUPPORTED`라 정확도 검증을 수행하지 못했다.
- 이는 현재 기능의 P0/P1 회귀는 아니지만, 정확도 주장과 운영 회고의 근거 공백이다.
- 최소 개선: 발표 시점 예보 스냅샷과 과거 관측을 버전된 fixture/저장소로 공급해 동일 계산 경로를 재생한다.

## 7. 검증 한계

이번 재감사 세션의 인앱 브라우저 런타임이 `No browser is available`을 반환했고 브라우저 목록도 비어 있었다. 도구 지침에 따라 재부팅 반복이나 다른 브라우저 자동화로 우회하지 않았다. 따라서 다음 항목은 최신 코드·정적 테스트로는 확인했지만 독립적인 실제 클릭 완료로 주장하지 않는다.

- 390px 모바일에서 `내 농장` 열기, 기존 농장 선택, `농장 추가`, 모달 닫힘
- 저장 동의를 끈 상태에서 분석 후 새로고침하여 localStorage 미기록 확인
- 마법사 `이전` 및 첫 단계 `돌아가기`의 화면 전환
- 모바일 OS/브라우저 뒤로가기

이 한계는 실제 백엔드와 프런트 프록시 API 흐름, 5작물 요청, 자동 테스트 결과에는 적용되지 않는다.
