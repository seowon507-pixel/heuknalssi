# 흙날씨 백테스트 기반 개선 계획

- 작성 기준일: 2026-08-04
- 기준 백테스트: 2025-08-04~2026-08-03, 365일
- 대상: 검수 ASOS 8개 지점, 사과·배·오이·감자·상추
- 기준 산출물: `one-year-backtest-2025-08-04-2026-08-03.json`

## 1. 결론

현재 구현은 과거 관측을 이용한 규칙 재생과 결측 방어를 기계적으로 수행할 수 있다. 다만 아래 이유로 제품의 예측 정확도가 입증된 상태는 아니다.

1. 과거 격자 API `nph-dfs_shrt_grd`로 2025-08-04~2026-08-03의 1일·3일 선행 최저·최고기온 예보를 8개 검수 지역에서 수집·검증했다. 하루 24개 시간별 POP를 빠짐없이 수집해 최대 POP로 일 확률을 만드는 검증기도 추가했다. 중기 육상·기온 과거자료도 연결해 같은 기간의 진정한 5일 선행 예보 2,920/2,920개를 ASOS 관측과 매칭했다.
2. 실제 파종·생육단계·피해·수확일 정답이 없어 실제 수치는 아직 계산할 수 없다. 대신 결과·예측·알림 CSV 계약과 수확 범위 오차, 피해 이벤트 재현율, 알림 정밀도 평가기를 구현했다.
3. 기존 수확 일정 민감도 검사는 실제 작기 없이 임의의 90일 구간을 사용했다.
4. 수확 일정 보정 적용 334건 중 241건(72.16%)이 ±14일 상한에 도달했고, 지연 보정은 0건이었다.
5. 과거 시점의 필지 토양 스냅샷 자체는 아직 없지만, 검정일이 분석일 이전인 최신 스냅샷만 선택하고 3년을 넘긴 값은 점수에서 제외하는 시점 일치 평가기를 구현했다.

따라서 현재 판정은 `FORECAST_D1_D3_TEMPERATURE_READY / FIVE_DAY_MEDIUM_TEMPERATURE_AND_POP_READY / FARM_OUTCOME_COLLECTION_READY_ACCURACY_NOT_PROVEN`이다. D+5 최저·최고기온과 강수확률은 1년 실자료로 측정했다. 실제 피해·수확 결과와 과거 필지 토양 정답은 아직 없으므로 해당 정확도 주장은 보류한다.

## 2. 개선 원칙

1. 현재 예보나 현재 토양값을 과거 날짜에 소급 적용하지 않는다.
2. 결측값은 0이나 평균으로 대체하지 않고 제외 사유와 함께 보존한다.
3. 작기와 생육단계가 없는 연중 임계값 발생률을 실제 사용자 알림률로 해석하지 않는다.
4. 날씨는 생육 속도에 대한 보조 근거이며 사진·센서 없이 생물학적 성숙을 확정하지 않는다.
5. 사용자가 확인한 작기·수확 범위가 자동 추정보다 우선한다.
6. 점수와 일정은 근거 강도 및 신뢰도를 별도로 노출한다.

## 3. P0 구현 범위

### 3.1 작물주기 기반 수확 일정 보정 v2

기존 방식은 관측기간 전체의 적산온도 차이를 일수로 환산해 ±14일로 자르는 방식이었다. v2는 다음과 같이 변경한다.

- 작물주기에 저장된 기준 수확 범위가 있을 때만 실제 일정 보정을 적용한다.
- 기준 수확 범위의 중간일까지 남은 기간과 관측/평년 적산온도 비율을 이용한다.
- 보정값으로 기준 수확 범위의 시작일과 종료일을 함께 이동한다.
- 최대 보정폭은 14일과 기준 수확 범위 폭의 25% 중 작은 값으로 제한한다.
- 이미 수확 범위가 끝났거나 작기가 `PLANNING`·`COMPLETED`이면 자동 보정을 적용하지 않는다.
- 결과에 기준 범위, 조정 범위, 적용 모드, 최대 보정폭, 신뢰도를 함께 기록한다.

이 제한은 정확도 보정값이 아니라 정답 데이터가 없는 상태에서 과도한 변동을 막는 제품 안전장치다.

일정 보정식은 다음과 같다.

```text
생육속도비 = 관측 적산온도 / 평년 적산온도
기준중간일 = 기준 수확 시작일 + (기준 수확 범위 폭 / 2)
남은일수 = max(0, 기준중간일 - 기준일)
원시보정일 = 남은일수 × (1 / 생육속도비 - 1)
최대보정일 = min(14, ceil(기준 수확 범위 폭 × 0.25))
최종보정일 = clamp(round(원시보정일 × 자료포함률), -최대보정일, +최대보정일)
조정 수확 범위 = 기준 수확 범위의 시작일·종료일 + 최종보정일
```

양수는 수확 예상 지연, 음수는 수확 예상 앞당김을 뜻한다. 이 값은 사진이나 실제 생체 측정 없이 성숙 여부를 확정하지 않는다.

### 3.2 작기·생육단계 필터

- 서비스의 위험 규칙은 요청의 현재 생육단계와 일치하는 규칙만 실행한다.
- 백테스트에서 생육단계 정답이 없는 규칙은 `stage_scoped_potential`로 분리하고 실제 알림으로 계산하지 않는다.
- 실제 작기 레코드가 확보되면 날짜별 CSV에 `season_id`, `cycle_status`, `growth_stage`, `rule_applicable`을 추가한다.
- 작기 종료 이후에는 신규 위험 행동과 수확 일정 보정을 만들지 않는다.

## 4. P1 데이터 검증 범위

### 4.1 과거 발행 예보

필요 데이터는 발행시각, 유효시각, 격자, 최저·최고기온, 강수확률이다. 과거 발행 예보 권한을 확인했으며 다음 중 기온 항목을 우선 계산했다.

사용할 공식 원천은 기상청 API허브의 `동네예보 격자자료 > 2.1 단기예보` (`nph-dfs_shrt_grd`)다. 최근 지점예보용 `getVilageFcst`는 운영 화면에는 계속 사용하지만 1년 백테스트의 과거 원천으로 사용하지 않는다.

- 1일·3일 선행 최고/최저기온 MAE·RMSE 완료
- 5일 선행은 단기예보 대신 과거 중기 육상·기온 발행본을 사용해 365일 × 8개 지역 검증 완료
- 강수 여부 정확도와 Brier score는 24개 시간별 POP가 모두 있는 날만 최대 POP로 일 단위 집계하여 계산. 일부 시간 결측일은 점수에서 제외
- 작물 위험 경보 정밀도·재현율
- 위험 발생 전 확보한 선행시간

예보 발행 이후에 생성된 관측값은 예측 입력으로 사용할 수 없다.

### 4.2 실제 농사 정답 데이터

최소 수집 항목은 다음과 같다.

- 농장·작물·작기 식별자
- 파종일 또는 정식일
- 생육단계 확인일
- 첫 수확일과 수확 종료일
- 피해 발생 여부와 확인일
- 사용자가 완료한 행동과 확인 사진

개인정보와 필지 원문 식별자는 분석용 내보내기에서 제외한다.

구현된 빈 CSV 계약과 실행 방법은 `product_upgrade_validation/backtest_1y/input_templates/README.md`를 따른다. 피해 기록이 없는 날을 자동으로 정상으로 취급하지 않으므로, 실제 데이터가 없는 상태에서 정확도를 만들어내지 않는다.

### 4.3 토양 전향 검증

- 필지 토양검정, 토양도 물리성, 지역 통계를 서로 다른 출처 등급으로 저장한다.
- 토양값마다 측정일, 조회일, 공간 범위, 출처를 보존한다.
- 토양검정 이력이 없는 경우 `토양검정 이력 없음`으로 표시하고 무료 토양검정 서비스로 연결한다.
- 현재 토양값을 과거 날짜의 정답으로 사용하지 않는다.
- 분석일 이후에 채취된 스냅샷은 선택 대상에서 제외하고, 선택된 값의 나이와 사용 가능 여부를 결과에 남긴다.

### 7.5 남은 위험과 다음 입력

1. 하루 24개 POP 집계와 Brier 계산을 구현하고 실제 공급자가 현재 제공하는 최대 과거 범위를 수집했다. D+1은 2,352/2,920쌍(80.55%, Brier 0.1213), D+3은 2,344/2,920쌍(80.27%, Brier 0.1330)이다. 과거자료 보존 범위와 최근자료 공개 지연 때문에 전체 365일은 한 시점에 완성할 수 없으며, 재개 가능한 추출 파일에 이후 날짜를 누적한다.
2. 5일 선행은 APIHub `fct_afs_wc.php`와 `fct_afs_wl.php`를 연결해 전체 365일 검증했다. 실제 typ01 응답의 12자리 발행시각, 행 종료 표식, 전체 공식 구역코드 형식을 계약 테스트에 고정했다.
3. `farm_id`, `crop_id`, `season_id`, 첫 수확일, 수확 종료일, 확정 피해일이 포함된 실제 기록을 빈 CSV 계약에 입력해야 실제 정확도가 산출된다.
4. 실제 작기 기록으로 작물별 수확일 MAE와 최대 보정폭 도달률을 재계산하기 전까지 v2는 안전한 일정 추정 로직이지 검증된 수확 예측 모델은 아니다.
5. 과거 토양 스냅샷 입력·시점 선택·노후도 차단은 구현했다. 실제 검정 이력을 입력하기 전까지 토양 기여도는 1년 재생에서 제외된다.

### 7.7 평창·대관령 공간 대표성 및 편향 보정 검증

평창군 중기예보는 `11D10503` 지역예보이고, 정답으로 사용한 ASOS는 해발 772.43m의 대관령(100) 단일 지점이다. 두 값은 모두 실제 기상청 자료지만 공간 단위가 서로 다르므로, 약 3.5°C의 오차를 API 실패로 해석하지 않는다.

이번 리비전은 다음 안전장치를 추가했다.

1. 기상청 공식 지점 목록에서 관측소 고도를 파싱하고 원 좌표·고도를 보존한다.
2. 농장 고도가 없으면 물리적 고도 보정을 적용하지 않는다. 거리만 가까워도 공간 대표성 신뢰도를 최고 단계로 올리지 않는다.
3. 원 예보는 수정하지 않고, 과거 90일의 `예보-관측 오차 평균`을 다음 예보에서 빼는 후보 보정을 별도 계산한다.
4. 후보 보정은 30일 학습 전에는 적용하지 않으며, 해당 예보 발행 전에 완료된 관측만 사용한다. 미래 관측 사용 건수는 0건이다.
5. 180개 이상의 무누수 비교쌍에서 MAE와 RMSE가 각각 0.1°C 이상 줄고 절대 편향도 감소한 지역·항목만 `VALIDATED_CANDIDATE`로 분류한다. 나머지는 원 예보만 사용한다.

전체 8개 지역의 후보 보정 공통 비교구간 2,635쌍에서는 다음과 같이 개선됐다.

| 항목 | 원 예보 MAE | 후보 보정 MAE | 원 예보 RMSE | 후보 보정 RMSE |
| --- | ---: | ---: | ---: | ---: |
| 최저기온 | 1.8301°C | 1.6182°C | 2.4184°C | 2.0802°C |
| 최고기온 | 1.9579°C | 1.7917°C | 2.5834°C | 2.3189°C |

평창·대관령 비교구간 325쌍에서는 최저기온 MAE가 3.5348°C에서 2.2017°C로, 최고기온 MAE가 3.6569°C에서 2.3020°C로 감소했다. 다만 이는 `지역예보 → 대관령 ASOS 지점`의 통계 보정 성능이며 농장 필지 기온 정확도를 의미하지 않는다. 농장 좌표의 고도 또는 현장 센서가 확보되기 전까지 물리적 고도 보정과 필지 기온 확정은 적용하지 않는다.
